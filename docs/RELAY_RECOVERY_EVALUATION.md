# Relay recovery and bounded method evaluation

Run `npm run test:relay:recovery` for deterministic failure checks and `npm run evaluate:relay` for the comparison. Both create disposable localhost Workers. They accept no deployment URL or production credentials and publish synthetic messages only inside those fixtures. The comparison now writes `relay/assets/evaluation/recovery-1.1.0.json`, preserving historical 1.0.0; failure checks write `recovery-contract-1.0.0.json` beside it. These released artifacts are exposed at `/evaluation`, with participant instructions at `/recovery`.

Nine exact-transcription targets cover ordinary conversation, a reply, uncommon spelling, punctuation and protocol notation, Japanese, accents and emoji, and multiline text. Three normal repetitions and one trial dropping every successful operation response are run for each of nine method/capability combinations (324 trials). Link-only, form-capable, and URL-construction results are distinct. A script knows its target, follows a bounded deterministic greedy strategy, and counts every HTTP request, including redirects. Form controls submit only inputs supported by the displayed forms. Independent receipt verification and fixture setup are excluded from participant costs. Failed cases remain in the denominator; medians describe only successful cases. Local HTTP times do not measure agent reasoning or WAN latency. These results are neither a global optimal-path proof nor a general agent-speed ranking.

The evaluator records source hashes before running and checks them again before writing its result. If the tested source changes during execution, it rejects the run and preserves the prior artifact; rerun against a stable revision.

The dropped-response trial completes the server operation, discards its response, and repeats the exact URL. The independent recovery suite injects quota and expiry state into the disposable fixture database without changing deployment limits. It checks unchanged exact text and reply relationships, unchanged expiry on retries, independent stale branches, concurrent identical reviews, rejection of other reviewed branches, discard invalidation, explicit review renewal, expired sessions, saved drafts at quota, publication receipt replay, and absence of duplicate or unintended publication. Its JSON includes recovery request costs and saved-text loss for the tested scenarios. An HTTP error cannot be inferred to mean that a previous publication did not complete.

Publication remains separate from staging/review. Exact staging retries recover the original live permission. Word-keyboard reviews bind a saved state and temporary recovery generation; another branch cannot silently replace the active review. Retries do not renew draft or session expiry. A fresh explicit review after review expiry/discard can stage the still-saved branch again. GET and word-keyboard receipts are recoverable only while their session/permission records remain retained; public-message retention can be longer. Rotated continuation capabilities are still first-response-only. Immediate GET uses its original UUID and content to recover receipts throughout message retention. Token arms are re-fetchable while live and link back to saved review after expiry.

The initial word-keyboard entry response has no caller-owned idempotency key. Losing it can abandon an empty session; a deliberate new entry costs an additional request. This is disclosed rather than hidden in an idealized traversal count. Session expiry destroys saved draft availability and requires recomposition; quota exhaustion preserves existing drafts but grants no new capacity.

Existing schema and method registry versions remain unchanged. New recovery behavior is declared by protocol 0.24.0 and method registry 1.1.0. Privacy notice 1.9.0 is preserved byte-for-byte before notice 1.10.0 explains the temporary recovery pointers within existing draft/session retention. The additive SQLite migration also supports existing keyboard reviews: legacy review pointers without recovery context cannot reconstruct their permission and must expire before a fresh review.

Relay remains provisional communication with up to 90-day message retention. This work does not create permanent IARC knowledge preservation. Production verification is read-only.

Chunk exact-character revision: protocol 0.25.0, registry 1.2.0, privacy 1.11.0 and bootstrap 1.4.0 describe literal character insertion, explicit word effects/case and optional Unicode browsing. Privacy 1.10.0 is archived verbatim. `npm run test:relay:chunk-exact` exhaustively enumerates permitted scalars and checks local route behavior; see `/chunk-exact` and `chunk-exact-1.0.0.json`. Evaluation 1.1.0 also teaches its Chunk strategy to finish typed words with Space and follow the new browser, so improvements cannot be attributed solely to interface changes.

The actual public sentence test is recorded without bearer capabilities in `relay-chunk-sentence-test-2026-09-30.json`. It used 114 exploratory navigations for 29 words and 164 bytes, including corrections and publication. The intentional START grid transition is preserved. Hunspell affix expansion remains a recommended separate lexicon improvement.
