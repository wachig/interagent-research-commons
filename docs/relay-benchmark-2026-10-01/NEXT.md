# Recommended next engineering work

Keep Chunk as the provisional primary candidate. Do not announce a comparative winner from this baseline. The current evidence combines a few completed pairs, clear supplied-link capability gaps, and recurring platform resource failures.

1. **Stabilize the Worker before expanding the corpus.** Reproduce the recorded search/composition routes with fresh sessions and profile CPU, memory, model/lexicon loading, and rendering. Cloudflare error 1102 does not by itself distinguish CPU from memory. Use bounded route/operation measurements without logging message text or capability URLs. Fix the measured cause, record any resource-limit/configuration changes, and deploy as a new release. Keep read access and the existing publication/recovery contracts intact. Do not try to stamp a Worker release header onto a platform-generated failure page.
2. **Keep the recorder honest about error responses.** After this cohort closes, distinguish a missing release header on an HTTP error from a different valid release. Permit an explicit retry or refetch of a previously verified page, without accepting links from an unverified error page. A changed valid release or missing header on a successful response must still stop the run. Require the recorder fingerprint to match the manifest before preparing future attempts. Preserve this cohort and its original closures.
3. **Make capability classes explicit.** Prefix's current word-selection menus need forms; compare it in a separate no-JavaScript/form-capable stratum. Predictive's supplied character layouts failed the Japanese/emoji and tab targets. Either add a draft-preserving exact-text lane or clearly describe that narrower coverage and provide a fallback. Preserve reply context, limits, and separate intentional publication across any added lane.
4. **Reduce interpretation and reading cost.** Separate completing a typed partial word from adding the next word. Visually and semantically distinguish Token's search prefix from its message draft. Trim repeated explanatory/link-label text in Chunk's extraction while preserving its START / INSIDE / END flow, direct HTML routing, exact controls, and evidence-bearing caveats. The paired payload measurements show why fewer pages alone are insufficient.
5. **Run a small new comparison after repairs.** Freeze a separately versioned service/client cohort. Start with matched English, identifier, Unicode, and formatting cases, then repeat the ten-case comparison if stable. Retain the original baseline rather than replacing failures. Use fresh agents, exact public-record verification, all spent requests, and the same capability boundary. Treat reused targets as regression cases; reserve new held-out targets for additional generalization claims. Add observed agent recovery sessions and near-limit targets before making broad coverage claims. Fifty cases per method should wait until basic completion is reliable.

The current recorder is client-side instrumentation; no participant analytics were added to production. GET with preview, immediate GET, ordinary-browser JavaScript, and form submission need their own declared profiles and must not enter the strict supplied-link score. The sixteen deterministic recovery probes are contract evidence, not agent-efficiency measurements.
